Prioritizing Content for Refresh: A Ranked, Evidence-Based Approach

Gopinath | FlyRank AI ML Internship Capstone | Lane: Refresh / Content Opportunity Scoring

Abstract

This paper builds a ranked content-refresh review queue for search-visible pages, using only observable search and content signals - never a product decision flag. A transparent baseline (three hand-written reason codes) is compared against a Random Forest model on the same client-grouped holdout split. The learned model outperforms the baseline on Precision@50, showing that a small set of observable signals can meaningfully rank refresh priority. Results are decision-support only.

1. Introduction / Problem Statement

Content teams cannot manually review every page every cycle. The decision this project supports: which pages should a reviewer look at first for a content refresh? A wrong call costs either wasted editing time (false positive) or a silently declining page left unreviewed (false negative).

2. Data

Modeling used the anonymized starter dataset (30,000 rows, one row = one content page over a 90-day window). Data-contract verification used the gated FlyRank/internship-warehouse release on Hugging Face, queried via DuckDB. No raw client names, URLs, or queries were used. No FlyRank product decision flags were used as features.

3. Methodology

Features: impressions_90d, sessions_90d, content_age_days, days_since_last_update, avg_position, ctr, word_count, engagement_rate.

Label (proxy): trend_direction == "down" - a current-window bucket, not a confirmed future outcome.

Baseline: a transparent rule combining three reason codes - stale_visible_page, declining_with_demand, low_ctr_visible_page.

Model: Random Forest Classifier (200 trees, balanced class weight).

Validation: client-grouped holdout split so no client's pages appear in both train and test.

Leakage checks: confirmed no product flags and no future-window data entered the feature set.

4. Results (vs Baseline)

The Random Forest model outperformed the transparent baseline on Precision@50 using the identical client-grouped split, indicating the model captures signal a fixed rule misses. Full numbers are in work/notebooks/capstone.ipynb.

5. Limitations

  • The label is a current-window proxy, not a validated future outcome.
  • No causal claim: this cannot prove a refresh will cause recovery.
  • Results are from a 30,000-row anonymized starter slice, not the full warehouse.
  • The warehouse history is an unbalanced panel.
  • No Google ranking algorithm factors are claimed.

6. Ranked Recommendations

The top-ranked pages combine staleness, visibility, and declining demand signals. These are observed, directional, decision-support recommendations. Full ranked table in work/notebooks/capstone.ipynb, Section 6.
